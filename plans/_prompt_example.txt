# Problem Definition

This tool is a vulnerability scanner that fetches cve information from several sources. 
We have made developments to version 1.1 where we moved from a 2 phased sequential pipeline to a new pipeline is a **three-phase, parallel, ungated** design. See plans/sprint-3-modular-scanner-architecture.md for the refactor details.

In this update scanning is terribly slow even tough we are using cache at many levels, we need you and your team to investigate and implemet the following requirements

## Scanning Choices

Currently there is a setting in config regarding scan that uses full or fast , lets make that an option.
Lets add a tab , left of the 'about' called settings.
In there a panel called shources should have all sources (all selected by default) but that the user can select.

The settings should be saved in the local database.


## Sources Credentials

Some sources are faster and have less rate limits if they are authenticated, for example github advisory can be authenticated by a apikey. Maybe other sources will do as well.

So add the possibility of having a credentials panel where the user can add an apiKey or token or watever required by source. The credentials should be saved in the internal encrypted database and never allow the user to see after added. Can be deleted , chanaged but not edited in plain text for security purposes.
