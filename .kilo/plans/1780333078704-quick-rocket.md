# Plan: Move MAX_FREE_FIXES to Constants & Change to 100

## Summary

The `MAX_FREE_FIXES` value (currently `10`) is hardcoded in `src/main/utils/trial-store.js` and duplicated as fallback magic numbers in two other files. This plan extracts it into the centralized constants module and updates the value to `100`.

## Affected Files

| File                            | Current State                                       | Action                                                                         |
| ------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------ |
| `src/main/config/constants.js`  | No trial config section                             | Add `TRIAL_CONFIG.MAX_FREE_FIXES = 100`                                        |
| `src/main/utils/trial-store.js` | Local `const MAX_FREE_FIXES = 10` (line 30)         | Import from constants, remove local definition, update JSDoc comment (line 19) |
| `src/main/main.js`              | Hardcoded fallback `fixesRemaining: 10` (line 1059) | Import constant, use it for fallback value                                     |
| `src/renderer/App.jsx`          | Fallback `?? 10` (line 506)                         | Import from renderer constants, use `?? MAX_FREE_FIXES`                        |
| `src/renderer/constants.js`     | No trial constant                                   | Add `export const MAX_FREE_FIXES = 100`                                        |

## Implementation Steps

### Step 1: Add `TRIAL_CONFIG` to `src/main/config/constants.js`

Add a new section between `LICENSE_CONFIG` and `DEP_UPDATES_CONFIG` (or after `LICENSE_CONFIG`):

```js
// ============================================
// TRIAL CONFIGURATION
// ============================================

/**
 * Trial/freemium usage limits for unlicensed users.
 * @namespace TRIAL_CONFIG
 */
const TRIAL_CONFIG = {
  /**
   * Maximum number of vulnerability fixes available in the free trial.
   * Once consumed, user must purchase a license to apply further fixes.
   * @type {number}
   */
  MAX_FREE_FIXES: 100,
};
```

Export `TRIAL_CONFIG` in the `module.exports` block.

### Step 2: Update `src/main/utils/trial-store.js`

- Remove line 30: `const MAX_FREE_FIXES = 10;`
- Add import at top (after existing requires): `const { TRIAL_CONFIG } = require('../config/constants');`
- Replace usage on line 172: `MAX_FREE_FIXES` → `TRIAL_CONFIG.MAX_FREE_FIXES`
- Update JSDoc comment on line 19: `max 10` → `max governed by TRIAL_CONFIG.MAX_FREE_FIXES`

### Step 3: Update `src/main/main.js` (line 1059)

- Line 6 already has: `const { UI_CONFIG, PAYPAL_CONFIG } = require('./config/constants');`
- Add `TRIAL_CONFIG` to that destructuring: `const { UI_CONFIG, PAYPAL_CONFIG, TRIAL_CONFIG } = require('./config/constants');`
- Change `fixesRemaining: 10` → `fixesRemaining: TRIAL_CONFIG.MAX_FREE_FIXES` in the error fallback

### Step 4: Add constant to `src/renderer/constants.js`

Add at the end of the file:

```js
/**
 * Maximum number of free trial fixes. Must match main process TRIAL_CONFIG.MAX_FREE_FIXES.
 */
export const MAX_FREE_FIXES = 100;
```

### Step 5: Update `src/renderer/App.jsx` (line 506)

- Import `MAX_FREE_FIXES` from `'./constants'`
- Change `?? 10` → `?? MAX_FREE_FIXES`

## Risks & Notes

- **Renderer/Main process separation**: The renderer (Vite-bundled) cannot `require()` main-process modules. That's why we add a separate `MAX_FREE_FIXES` export in `src/renderer/constants.js`. A comment clarifies it must stay in sync with the main process constant.
- **No circular dependency risk**: `trial-store.js` already requires `../modules/license` lazily. Requiring `../config/constants` at module top level is safe (constants has no side effects).
- **The `n % 10 === 0` in App.jsx (line 463)**: This is unrelated — it controls how often the "buy" modal is shown during scans (every 10th scan). It is NOT the free fixes limit and should NOT be changed.
